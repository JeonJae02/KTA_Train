# C05 — 행거 이송장치 구동부 체인 이탈, 라인 스톱 2회 (2026-11-03)

> 근거 노트북: [`../C04_C05_행거.ipynb`](../C04_C05_행거.ipynb) · 그림: `../figs/C05_drive_restart.png` · 모델 코드: v2.2 (11-03 엣지는 v2.1, 컨베이어 코어 코드는 같다) · 작성 2026-11-13

## 한 줄 결론

**모델 범위 밖(`OUT`)이다.** 행거 이송장치는 2라인 PLC 밖 설비라 신호가 들어오지 않는다. 2라인은 일지와 같은 시각에 섰지만 **알람 없이** 섰다. 행거가 서니 작업자가 세운 것이다.

같은 시간대에 W0205 "구동부 속도 → 구동부·체인 점검"(sev 3)이 떴지만, 행거를 본 것이 아니다. 재가동할 때마다 3~6분씩 깜빡인 **재가동 과도**다 → `FP`. 대차 컨베이어 구동 지표는 정상이었다.

이걸 따라가다 보니 구동부 경고 전체의 문제가 나왔다. 엣지 구동부 경고 25번 중 16번이 재가동 10분 안이다. 판정을 시작하는 최소 표본(100개)이 문턱(0.3%)에 비해 작다 → [모델 수정 예정 C-06](../../모델_수정_예정.md#c-06-구동부-속도-판정은-재가동-직후-표본이-적을-때-문턱을-넘는다).

## 1. 일지

| 작업ID | 시각 | 라인 | 내용 | 결과 |
|---|---|---|---|---|
| M-02-02-2-5 (기계실) | 11-03 17:00~18:26 · 20:45 · 21:21~22:26 | 미기재 (발포) | 행거 이송장치 구동부 쪽 체인 이탈로 라인 스톱 → 같은 현상으로 다시 라인 스톱 → 라인별 부분생산 → 수리 완료 | 22:26 이후 정상 가동. 생산영향: 라인 스톱 2회, 부분 생산 |

- 3일 전 10-31에 같은 설비 체인 텐션을 점검했다([C04](C04.md)).
- "라인별 부분생산"을 보면 행거는 여러 라인이 같이 쓰는 설비로 보인다.

## 2. 그때 2라인은 — 일지와 같은 시각에 알람 없이 섰다

| 2라인 컨베이어 | 시각 | 일지 | 정지 순간 알람 워드 |
|---|---|---|---|
| 수동으로 몇 번 돌렸다 세움 | 16:59 ~ 17:13 | 17:00 체인 이탈 | 0 |
| **정지** | **17:13 ~ 18:26** | 17:00 ~ 18:26 라인 스톱 | 0 |
| 운전 | 18:26 ~ 19:30 | | |
| 정지 (정기 휴식) | 19:30 ~ 20:05 | | 0 |
| 운전 | 20:09 ~ 20:52 | | |
| **정지** | **20:52 ~ 21:23** | 20:45 같은 현상으로 라인 스톱 | 0 |
| 운전 | 21:23 ~ 22:08 | 21:21 ~ 22:26 부분생산 | |
| 정지 (정기 휴식) | 22:08 ~ 22:20 | | 0 |

- 재가동 시각까지 일지와 맞는다(18:26, 21:23). 21:21 ~ 22:26 "부분생산" 동안 2라인은 돌았다.
- 19:30, 22:08 정지는 10-31에도 같은 시각에 있던 정기 휴식이다.
- **정지 순간 알람 워드가 모두 0이다.** 2라인 PLC 인터록이 아니라 작업자가 세웠다.
- 대차 컨베이어 속도 비율(40.5 Hz 정속, 시간별)은 0.2742 ~ 0.2745로 기준(0.2744) 그대로다. 대차 컨베이어 체인·구동부에는 변화가 없다.

## 3. 그때 모델은 무엇을 냈나, 왜

### 3-1. W0205 구동부 속도 — 재가동할 때마다 깜빡임

| 엣지 이벤트 | 시각 | 직전 재가동 |
|---|---|---|
| 켜짐 → 꺼짐 | 18:29:22 → 18:32:53 | 18:26:45 (2.6분 전) |
| 켜짐 → 꺼짐 | 19:59:49 → 20:02:19 | 19:59:18 (0.5분 전) |
| 켜짐 → 꺼짐 | 21:20:41 → 21:26:43 | 정지 중(20:52 ~ 21:23)에 켜짐, 21:23:50 재가동 뒤 꺼짐 |

구동부 판정은 30분 창에서 정속 샘플의 "카운터 증가 ÷ (Hz × 시간)"을 기준(0.2744)과 비교한다. 정속 표본이 100개 이상일 때 판정하고, 0.3% 넘게 벗어나면 sev 3이다.

- 정지가 30분 넘으면 속도 창이 빈다. 재가동 뒤 정속 표본이 100개(약 1분)를 넘으면 판정을 다시 시작하는데, 바로 그때 편차가 가장 크게 흔들린다.
- **DB 재생(샘플마다)도 엣지와 같은 초에 문턱을 넘는다.**

| 재가동 | DB 재생 최대 편차 | 그때 (표본) | 엣지 켜짐 |
|---|---|---|---|
| 18:26:45 | −0.34% | 18:29:23 (212개) | 18:29:22 |
| 19:59:18 | −0.39% | 19:59:50 (137개) | 19:59:49 |
| 21:23:50 | −0.56% | 21:25:43 (105개) | 21:20:41 (DB 운전 출력상 정지 중 — 시각이 맞지 않음) |

- 표본이 늘수록 편차는 −0.05% 안팎으로 돌아오고 경고도 꺼진다.

### 3-2. 구동부 경고 전체 — 재가동 과도가 대부분이다

엣지 구동부 경고(`drive_speed`)가 켜진 25번(10-26 ~ 11-06)을 직전 재가동과 비교했다.
- **16번이 재가동 10분 안이다.**
- 시각은 06:1x, 11:1x ~ 11:3x, 19:5x, 00:3x ~ 01:1x에 몰려 있다. 아침 시작, 점심, 저녁, 자정 휴식 직후다.

재가동마다 "정속 표본이 N개 찼을 때의 편차"를 DB로 계산했다(10-27 ~ 11-05 재가동 151번).

| 정속 표본 | 재가동 뒤 경과 (중앙값) | 카운트 | 편차 표준편차 | 문턱 0.3% 넘는 비율 |
|---|---|---|---|---|
| **100 (지금 판정 시작점)** | 98초 | 561 | 0.29% | **20%** |
| 200 | 179초 | 1,118 | 0.25% | 15% |
| 400 | 331초 | 2,239 | 0.22% | 5% |

재가동 뒤 30분 정속 평균은 −0.007%다. 구동부는 멀쩡한데 판정 시작점에서 다섯 번에 한 번은 문턱을 넘는다.

## 4. 모델의 의미 vs 현장의 의미

| | 모델 (W0205) | 현장 |
|---|---|---|
| 대상 | 대차 컨베이어 구동부·체인 | 행거 이송장치 구동부 체인 |
| 무엇 | 속도 비율이 기준에서 벗어남 | 체인 이탈로 라인 스톱 |
| 시점 | 재가동 직후 3~6분씩 세 번 | 17:00 ~ 22:26 |

대상이 다른 구동계다. 게다가 W0205는 재가동 과도라 대차 컨베이어에 대해서도 맞는 경고가 아니다.

## 5. 이 사건은 어떤 피처로 봐야 하나

| 피처 | 이번 사건에서 | 판단 |
|---|---|---|
| 대차 컨베이어 속도 비율 (`drive_speed`) | 정상 (재가동 직후 깜빡임만) | 행거와 다른 구동계. 이 사건을 볼 수 없다 |
| 2라인 "알람 없는 정지" | 일지와 같은 시각 | 다른 설비(행거 등) 때문에 섰다는 흔적일 뿐, 원인은 모른다 |
| 행거 자체 | — | 행거 쪽 신호(구동 모터 전류·속도, 체인 이탈 L/S, 행거 PLC 알람)가 있어야 한다. 지금 수집 범위 밖 |

## 6. 판정

| 항목 | 값 |
|---|---|
| 사건 C05 `cm` | **OUT** — 행거는 2라인 PLC 밖 설비. 신호가 들어오지 않는다 |
| 모델범위 | **아니오** (action_map의 "애매"에서 바꿈) |
| `matched_episodes` | 없음. 같은 시간대 W0205는 짝이 아니다(다른 구동계, 재가동 과도) |
| `feature_shift` | 없음 — 대차 컨베이어 속도 비율 그대로. 2라인은 알람 없이 정지(17:13 ~ 18:26, 20:52 ~ 21:23) |
| 경고 W0205 (11-03 18:29 ~ 21:26, `drive_speed`) | **FP / 재가동과도** — 재가동 직후 3~6분씩 세 번. 정속 속도 비율 정상 |
| 다른 구동부 경고 24건 | 라벨 안 함. 같은 패턴으로 보이지만(16/25가 재가동 10분 안) 하나씩 확인은 안 했다. 구동부 경고를 따로 묶어 볼 때 정한다 |
