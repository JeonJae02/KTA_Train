# 예지보전 모델 검토 계획

> 2026-11-04 회의용 초안 · 작성 2026-11-03
> 검토 대상 코드·모델: HDI_Relay `cd73ba2` (hotfix 브랜치)를 그대로 복사한 이 폴더(`DB_Log/model_review_1103/`)

## 1. 한눈에 보기

예지보전 경고는 실시간으로 잘 뜨고 있다. 하지만 그 경고가 맞는지는 아직 확인한 적이 없다. 펌프 모델은 10월 초까지의 데이터로 만들었고, 운영에 올라간 지 2~3주가 지났다. 이 기간의 데이터와 현장 일지로 다음 세 가지를 확인한다.

| # | 질문 | 보는 것 | 결과물 |
|---|---|---|---|
| 1 | 학습 때의 '정상'이 지금도 정상인가 | 학습 이후 데이터로 다시 그린 분포와 다시 맞춘 기준선 | 모델·지표별 기준선 비교표 |
| 2 | 실무자가 손댄 곳을 우리도 봤는가 | 우리 경고 이력과 일지의 조치 기록 | 맞춤·놓침·미확인 경고 목록 |
| 3 | 조치하면 데이터가 어떻게 바뀌는가 | 조치 전후의 같은 지표 | 조치별 전후 변화표 |

세 검토는 같은 재료 세 가지를 쓴다. 원시 PLC 데이터, 우리 예측 결과, 정리한 일지다. 그래서 재료 준비를 먼저 나눠 맡고, 1번과 2번은 병렬로, 3번은 두 결과를 받아서 진행하는 순서를 제안한다.

> **회의에서 꼭 정해야 시작할 수 있는 것:** 모델별 검토 기간, 일지 표기와 우리 설비의 대응표, 경고와 조치를 짝짓는 시간창. 나머지 결정 사항과 분담은 [5절](#5-회의에서-정할-것--분담)에 모았다.

## 2. 검토 대상 — 모델과 기간

모델마다 기준을 만든 방식과 시기가 다르다. 그래서 "학습 이후"의 시작일도 모델마다 다르다.

| 대상 | 판정 방식 | 기준을 만든 데이터 | 운영 반영 (버전 표기) |
|---|---|---|---|
| 펌프 14대 (P1–P7, I1–I7) | 사이클 오토인코더 + 펌프별 기준선 | 기준선 09-10 ~ 10-03, 오토인코더 학습 ~09-27·검증 09-28 ~ 10-04 | v2.1.0 (261016) |
| 탱크 8개 (히터·열교환기·쿨러) | 고정 규칙 3개, 학습 없음 | — | v2.1.0 (261016) |
| 헤드 인젝션 7개 | 고정 문턱 (ON_T 17초, OFF_T 10초) | — | v2.1.0 (261016) |
| 컨베이어 코어 센서 6개 | 장기 기준 + 지난 가동일 기록 | 장기 기준 09-10 ~ 09-19, 기록 09-10 ~ 10-19 | v2.1.1 (261026) |
| 컨베이어 유닛 3곳 | 지표별 장기 기준 ± 날짜 간 흔들림 | 09-10 ~ 10-19 | v2.1.1 (261026) |

이 표에서 검토 방식이 갈린다.

- **다시 맞출 기준선이 있는 것은 펌프와 컨베이어뿐이다.** 탱크와 헤드는 문턱이 고정이다. 이 둘은 "지표 분포가 문턱에 비해 어떻게 움직였나"를 본다.
- **펌프의 10-05 이후는 학습 때 시험 구간으로 남겨 둔 기간이다.** 기준선과 오토인코더 학습에는 쓰지 않았다. 컨베이어 유닛은 10-19까지 기준에 들어갔으므로 학습 이후 구간이 2주 남짓이다.
- **컨베이어는 운영 1주 남짓이다.** 2번·3번 검토의 표본이 적으니 사례 위주로 본다.
- **탱크 I2·P5는 경보를 끈 상태다.** 설정이 안 맞아 판정만 돌고 경고는 내보내지 않는다. 그래서 경고 이력에 남지 않고, 재생으로만 확인할 수 있다.
- **운영 반영일은 버전 표기일 뿐이다.** 엣지에 실제로 올라간 날짜는 확인이 필요하다. 경고 이력 파일의 첫 줄 시각으로도 확인할 수 있다.

모델별 상세 수치(피처, 임계값, 학습 때 성능 기록)는 [부록 B](#b-모델별-상세-수치)에 있다.

## 3. 재료 준비

### 3-1. 원시 PLC 데이터

엣지 InfluxDB에서 뽑는다. 기간은 모델별 기준 기간과 학습 이후 기간(~11-03)을 **둘 다** 뽑는다. 같은 추출·전처리를 거친 값끼리 비교해야 기준선 차이가 처리 방식 차이와 섞이지 않는다.

- **태그 목록은 코드에서 뽑는다.** 펌프 90개, 컨베이어 46개, 탱크 40개, 헤드 21개, 가동 플래그(`Auto_Running_PL`)다. 뽑는 코드는 [부록 A](#a-작업-폴더-사용법)에 있다.
- **값은 엣지가 받는 원시값 그대로 둔다.** 모델이 단위 변환(예: 탱크 온도 0.1℃ → ℃)을 직접 한다.
- **기존 캐시를 활용할 수 있다.** `DB_Log/cache/pump_raw`는 10-12 무렵까지, `DB_Log/cache/conv_raw`는 10-25 무렵까지 있다(manifest 기준). 모자란 기간만 추가로 뽑는다.

### 3-2. 우리 예측 결과

출처가 두 가지이고 쓰임이 다르다.

| 출처 | 담긴 것 | 쓰는 곳 | 한계 |
|---|---|---|---|
| 엣지 경고 이력<br>`backend/logs/predictive_warnings/warnings.jsonl*` | 화면에 뜬 경고의 raised·updated·cleared 시각, 사유, 문구 | 2번 — 실무자에게 실제로 보인 것 | 상태 변화만 남아 점수 연속값이 없다. 재시작 때 경고 하나가 둘로 쪼개진다. 컨베이어는 v2.1.1부터 기록됐다. 90일 지나면 지워진다 |
| 재생 — 이 폴더의 모델에 원시 데이터를 다시 흘림 | 틱 단위 점수·등급, 판정 없음 여부, 경보를 끈 탱크의 판정 | 1번·3번의 연속 지표, 2번 놓침 분석 | 엣지와 코드는 같지만 재시작·수집 공백까지 똑같이 재현되지는 않는다 |

모바일 서버의 경고 이력은 엣지 로그가 비는 구간을 확인하는 용도로만 쓴다.

**경고 이력은 "경고 한 건 = 한 행" 표로 정리한다.** 같은 대상·같은 사유의 raised부터 cleared까지를 한 건으로 묶는다. 재시작으로 끊긴 조각은 공백이 짧으면(초안 30분) 합친다.

| 열 | 내용 |
|---|---|
| kind / key | `pump`·`relay`·`conveyor` / P1, 릴레이 주소, conv 키 |
| 설비키 | 일지와 맞출 공통 키 — topology 설비 ID (`PUMP_P1`, `TANK_I3`, `HEAD_HD1`, `CONVEYOR`) |
| reason / type / message | 경고 사유 코드, 아이콘 종류, 화면 문구 |
| first_raised | 처음 뜬 시각 |
| last_detected | 마지막으로 이상 조건이 성립한 시각 |
| cleared | 화면에서 내려간 시각 |
| n_split | 합친 조각 수 |

정리할 때 주의할 점이 둘 있다.

- **시각은 한국시간으로 바꾼다.** 로그는 UTC(`...Z`)이고 일지는 한국시간이다.
- **짝짓기에는 cleared가 아니라 first_raised와 last_detected를 쓴다.** 경고는 이상이 해소돼도 다음 근무 구간이 끝날 때까지 화면에 남는다. 그래서 cleared는 근무 구간이 끝나는 시각(08:50, 10:50, 13:30 등 하루 8개)에 몰린다.

### 3-3. 일지

08-31 ~ 10-19분은 이미 `DB_Log/기계실_공무반_정리/`에 정리돼 있다(`01_이슈조치.csv`, 작업 175건). 10-20 이후분은 **같은 열 구성으로** 정리해서 이어 붙인다. 그리고 우리 검토에 필요한 열 세 개를 더한다.

| 추가 열 | 내용 | 값 예시 |
|---|---|---|
| 설비키 | 3-2와 같은 topology 설비 ID. 우리 모델 대상이 아니면 빈칸 | `PUMP_P4`, `TANK_I3`, `HEAD_HD1`, `CONVEYOR` |
| 모델범위 | 우리 모델이 데이터로 볼 수 있는 고장인가 | 예 / 아니오 / 애매 |
| 발견경위 | 무엇을 보고 조치했나 (일지에 적혀 있을 때만) | 순회점검, 설비 알람, 작업자 신고, 우리 경고, 미기재 |

이 열들을 채우는 기준은 다음과 같다.

- **설비키는 표기 대응표가 먼저다.** 일지는 "2-2 POLYOL 펌프"처럼 적고, topology 이름은 "2-2펌프 HARD"(`PUMP_P4`)다. 일지의 라인번호·공정표기(발포/COLD)가 우리 PLC가 보는 설비와 어떻게 맞는지도 확정해야 한다. 이 대응표는 회의에서 정한다.
- **모델범위는 부록 B의 진단 사유표를 기준으로 판단한다.** 예를 들어 촉매 다이어프램 펌프나 로봇축은 우리 모델이 보지 않으므로 '아니오'다.
- **발견경위가 '우리 경고'인 건은 2번에서 따로 센다.** 실무자가 우리 화면을 보고 움직였다면 그 건은 독립적인 비교가 아니다. 3번(조치 영향)에서는 그대로 쓴다.
- **정기점검·예방 교체는 '문제가 있었다'는 근거가 아니다.** 2번의 분모는 `01_이슈조치` 기준으로 잡는다. 정기점검 기록(`02_전체업무`)은 3번의 전후 비교 대상으로 쓸 수 있다.
- **작업일이 빈 행은 시간창 비교에서 뺀다.** 기존 정리본의 `기준일`은 정렬용이라 실제 작업일로 쓰면 안 된다.

## 4. 세 가지 검토

### 4-1. 기준선 재확인 — 학습 때의 정상이 지금도 정상인가

**질문.** 학습 이후 데이터를 학습 때와 같은 방식으로 다시 그리고 다시 맞췄을 때, 기준선이 학습 때의 날짜 간 흔들림 안에 머무는가.

**순서**

1. 학습 기간과 이후 기간을 같은 전처리로 처리한다. 펌프는 이 폴더의 `pump_preprocess`로 사이클 피처를 뽑는다. 컨베이어는 재생으로 하루 마감 기록을 만든다.
2. 아래 목록대로 그린다.
3. 학습 때와 같은 방법·같은 설정으로 새 기간에 기준선을 다시 맞춘다.
4. 학습 때 기준선과 새 기준선을 비교하고, 아래 판정표로 분류한다.

**그릴 것**

- **펌프 피처 히트맵.** 펌프 × 피처 8개(펌프 잔차, 압력/기대, 응답 시간, 감속 반감, 압력 해제 반감, 유량 흔들림, 압력 흔들림, 시작 전 압력)를 날짜별로 그린다. 값은 일별 중앙값을 학습 기준선 대비 z로 바꾼 것이다.
- **펌프 점수와 알림률.** 일별 오토인코더 점수 분포를 경고 임계선과 같이 그린다. 알림률은 학습 때 기록과 같은 단위로 비교한다(학습 때 새 날 정상 펌프 0.37건/펌프·일, 사이클 1.68%).
- **펌프 판정 없음 비율.** 학습 범위 밖 조건이 늘면 모델은 경고를 내는 대신 침묵한다. 그래서 침묵이 늘었는지 일별로 본다.
- **펌프 조건 범위.** 원료 온도가 학습 범위(예: P1 19.4 ~ 23.7℃)를 벗어나는지 확인한다. 회전수 단계가 학습에 없던 조합인지도 본다. 11월 들어 기온이 내려가면 가장 먼저 걸릴 수 있는 항목이다.
- **컨베이어 코어.** 센서별 일별 위치(D)·켜짐 길이(W)·흔들림(J)을 장기 기준과 같이 그린다. 구동부 속도 비율 K는 기준 0.2744(31 가동일 ± 0.0001)와 같이 그린다.
- **컨베이어 유닛.** 지표별 일별 값을 장기 기준 ± σ 띠와 같이 그린다.
- **탱크.** 열교환기 켜짐 시간 분포(문턱 600초), 쿨러 동반 연속 횟수(문턱 10회), PV − L_Set 최소값을 그린다. I2·P5는 재조정 근거를 만들기 위해 같이 본다.
- **헤드.** ON_T·OFF_T 분포와 문턱(17초, 10초)까지의 여유를 그린다.

**다시 맞추기**

- **펌프는 기준선과 오토인코더를 둘 다 다시 맞춘다.** 설정은 `meta.json` 그대로 쓴다. 처음 학습 절차도 `meta.json`과 baseline JSON에 기록돼 있다(`generated_by`, `threshold_method`).
- **비교는 두 겹으로 한다.** 하나는 계수·임계값 자체의 차이다. 다른 하나는 같은 데이터를 옛 모델과 새 모델로 채점했을 때 경고가 얼마나 달라지는지다. 운영에 직접 의미가 있는 것은 뒤쪽이다.
- **새 기간에도 이상 구간이 섞여 있다.** 일지에서 이슈·조치가 있던 설비·날짜는 빼고 맞춘다. 학습 때도 같은 방식으로 날짜와 사건을 뺐다(`exclude_days`, `events`).
- **컨베이어는 같은 정의로 다시 계산한다.** 코어는 앞 구간 중앙값, 유닛은 처음 3 가동일 중앙값과 연속한 날 차이 기반 σ다.

**판정표 (초안, 회의에서 확정)**

"날짜 간 흔들림"은 학습 기간 일별 중앙값의 MAD(중앙값 절대 편차)로 잡는다.

| 결과 | 해석 | 다음 행동 |
|---|---|---|
| 이동이 날짜 간 흔들림 안 | 기준선 유지 | 없음 |
| 조치 날짜를 경계로 계단처럼 이동 | 정비 후 새 정상 | 그 설비의 기준선 갱신 후보. 4-3과 같이 확인 |
| 한 방향으로 서서히 이동 | 열화 또는 운전 조건 변화 | 경고가 떴는지 4-2에서 확인. 현장 확인 요청 |
| 조건 범위 밖 비율 증가 | 모델이 판정을 못 하는 중 | 학습 범위 확대 |
| 여러 펌프가 같은 날 함께 이동 | 공통 원인 (원료 로트, 기온, 레시피) | 개별 설비 문제로 보지 않음 |

### 4-2. 예측 vs 실무자 조치 — 실무자가 본 것을 우리도 봤는가

**질문.** 실무자가 조치한 설비에 대해 우리 경고가 조치 전에 떴는가. 반대로 우리가 띄운 경고 중 조치로 이어지지 않은 것은 무엇인가.

**짝짓기 규칙 (초안)**

- **같은 설비키이고, 경고가 조치 전 7일 안에 처음 떴으면 짝으로 본다.** 7일은 회의에서 정한다.
- **조치 시각은 일지의 작업일과 기록시간 시작으로 잡는다.**
- **조치 뒤에 처음 뜬 경고는 '사후'로 따로 센다.** 재가동 직후의 과도 상태이거나 조치가 효과 없었을 수 있다.

**분류**

| 분류 | 조건 | 더 볼 것 |
|---|---|---|
| 맞춤 | 조치 전 시간창 안에 같은 설비 경고 | 선행 시간(처음 뜬 시각 → 조치 시각), 경고 사유와 실제 조치 부위가 맞는지 |
| 놓침 | 모델범위 '예'인 조치에 경고 없음 | 재생 점수가 문턱 아래에서 움직였는지, 판정 없음이었는지 |
| 범위 밖 | 모델범위 '아니오'인 조치 | 분모에서 빼고 건수만 남긴다. 모델 확장 후보 |
| 미확인 경고 | 경고는 있는데 짝지을 조치가 없음 | 바로 오탐으로 보지 않는다. 현장 확인 목록으로 넘긴다 |

분류에 대한 보충 기준은 셋이다.

- **맞춤은 세 단계로 나눈다.** 부위까지 맞음, 설비만 맞음, 불일치다. 예를 들어 경고 "유량계 측정 이상"에 조치 "유량계 교체"면 부위까지 맞음이다. 경고 "펌프 토출 저하"에 조치 "노즐 청소"면 설비만 맞음이다.
- **미확인 경고를 오탐이라 부르지 않는 이유가 있다.** 일지에 안 적은 점검, 아직 진행 중인 열화, 보고 넘어간 판단이 모두 가능하다.
- **발견경위가 '우리 경고'인 건은 따로 표시한다.** 독립적인 맞춤이 아니기 때문이다.

**결과 정리**

설비별·모델별로 범위 안 조치 수, 맞춤, 놓침, 미확인 경고 수, 선행 시간 중앙값을 표로 만든다. 다만 표본이 몇십 건이라 비율은 크게 흔들린다. 그래서 **비율보다 사례 목록을 먼저** 본다.

### 4-3. 조치 영향 — 조치하면 데이터가 어떻게 바뀌는가

**질문.** 실무자의 조치 전후로 우리 지표가 움직였는가. 움직였다면 조치가 효과가 있었고 우리 지표가 그 고장에 민감하다는 뜻이다. 안 움직였다면 둘 중 적어도 하나는 아니다.

**순서**

1. 모델범위가 '예'나 '애매'인 조치마다 전후 N일 창을 잡는다. 조치 당일의 작업 시간과 재가동 직후 사이클은 뺀다.
2. 4-1과 같은 지표로 전후를 비교한다. 펌프는 피처 z·점수·알림률, 탱크·헤드는 사이클 지표, 컨베이어는 센서·유닛 지표다.
3. 차이를 학습 때 날짜 간 흔들림으로 나눠 크기를 맞춘다.
4. 같은 기간에 조치가 없던 같은 종류 설비의 변화를 빼고 비교한다. 원료·기온처럼 라인 전체에 걸리는 변화를 이렇게 걸러낸다.

**결과 해석**

| 전후 변화 | 해석 | 연결 |
|---|---|---|
| 이상에서 기준선 근처로 복귀 | 조치 효과 있음, 지표 유효 | 4-2에서 맞춤이었다면 가장 강한 근거 |
| 변화 없음 | 조치가 이 지표와 무관하거나 효과 없음 | 재발 여부 확인. 그 부위 고장은 모델이 못 보는 것일 수 있음 |
| 새 수준으로 계단 이동 | 조치 후 새 정상 | 4-1의 기준선 갱신 후보 |
| 조치 후 악화 | 부작용 또는 재가동 과도 상태 | 며칠 뒤 안정되는지 확인 |

**방법 검증용 사례를 먼저 돌린다.** 학습 때 이미 표시해 둔 사건 두 개가 일지 기간(08-31 ~) 안에 있다.

- **I3 09-18 계단 (+5%).** 학습 때 "작업 전으로 추정"이라고만 적었다. 일지에서 그날 I3(2-1펌프 MDI) 작업이 확인되면 4-3 방법이 제대로 잡는지 볼 수 있다.
- **P2 배관 저항 +7% (10-06 ~).** 이후 조치 기록이 있으면 전후 비교 사례가 된다.
