# 추세 변수 정리 — 탱크 · 헤드

지금 탱크와 헤드 모델은 **한 번 넘으면 이상**인 문턱 규칙이다(10분 초과, ON_T ≥ 17 등).
이 문서는 나중에 붙일 **추세 판단**에 쓸 변수 후보를 정리한 것이다. 추세 판단은 "아직 문턱은 안 넘었지만 점점 나빠지고 있다"를 잡는 것이다.

메시지 문구에 이미 추세가 들어가 있다. 예: `"열교환기 냉각 응답 지연 · 설정 온도 복귀 시간 증가 추세"`, `"인젝션 (로드) 작동 시간이 길어지고 있습니다"`. 아래 변수들이 그 "증가 추세"의 실제 근거가 된다.

---

## 0. 공통 원칙

### 기준값(baseline)은 장비별로, 계속 갱신한다

- 탱크와 펌프마다 정상 범위가 다르다. 예를 들어 탱크 exchanger 사이클 중앙값은 P4 가 92초, P3 가 214초다. 그래서 공통 문턱을 쓰지 않고 **각자 자기 기준값과 비교**한다.
- 계절이나 외기 온도에 따라 정상값 자체가 움직인다. 그래서 고정값 대신 **최근 N 운영일(예: 7일)의 일별 통계 중앙값**을 기준으로 삼고, 매일 갱신한다.
- 비교는 `최근 / 기준` 비율이나, 중앙값·MAD 같은 이상치에 강한 통계로 한다. 평균과 표준편차는 정지 후 재가동 때 한 번 튀는 값에 끌려간다.

### 가동 중 데이터만 쓴다

- `Auto_Running_PL == 1` 일 때 시작한 사이클만 추세 계산에 넣는다.
- 아침 예열 구간(05~06시)은 비가동 사이클이 10분을 넘는 비율이 3.88% 로, 가동 중(0.15%)과 완전히 다르다. 여기를 섞으면 추세가 아니라 "어제 아침 예열이 길었다"를 보게 된다.
- 정지 후 첫 사이클은 뺀다. 헤드 타이머는 재가동 직후 값이 크게 튄다(`Injection_Timer_Stable_Duration_Analysis.py` 참고).

### 실시간으로 계산하는 방식

```
사이클 완료 이벤트 ─▶ 최근 N개 deque ─▶ 롤링 통계 (중앙값, p90, 문턱 근접 비율)
                         │
오전 6시 ──────────────▶ 일별 요약 1행 저장 ─▶ 최근 7운영일 → 기준값
```

- 사이클 단위 값은 `deque(maxlen=N)` 에 넣는다. 메모리는 상수다.
- **일별 요약은 재시작해도 남아야 한다.** 파일이나 DB 같은 영속 저장소에 저장해야 하며, 이 점이 지금의 규칙 모델과 다르다. 하루 한 행이라 크기 부담은 없다.

### 추세 판정 방식 후보 (단순한 것부터)

1. **비율**: 오늘(또는 최근 N사이클) 중앙값 / 기준 중앙값 > k
2. **기울기**: 최근 D일 일별 지표의 Theil-Sen 기울기 > 0 이고 유의할 때
3. **누적합(CUSUM)**: 기준에서 조금씩 벗어나는 걸 누적한다. 작은 변화에 민감하지만 튜닝이 필요하다.

→ 1 과 2 로 시작하고, 문턱 k 는 데이터를 더 모은 뒤 정한다. 지금 데이터는 9/9 이후 약 4주, 계절 하나뿐이다.

## 1. 탱크

### 1-1. exchanger 사이클 단위 (사이클이 확정될 때마다 1개)

`TankRealtime._close_cycle()` 에서 이미 나오는 값이 대부분이다.

| 변수 | 정의 | 의미 | 지금 계산하는가 |
|---|---|---|---|
| **`on_duration_sec`** | cycle_start ~ 실제 꺼진 시각 | **설정 온도 복귀 시간.** 핵심 지표. exchanger 효율이 떨어지면 길어진다 | ○ |
| `off_duration_sec` | 꺼진 뒤 다음 켜짐까지 | 온도가 다시 오르는 속도. 열부하·외기 영향을 받는다 | △ (다음 사이클 시작 때 계산 가능) |
| `duty` | on / (on + off) | 시간당 냉각이 차지하는 비율. 부하 변화를 일부 상쇄한다 | × |
| `n_bridged` | 사이클 안에서 이어붙인 짧은 OFF 수 | SV 근처 들썩임 횟수. 제어·센서 상태 | × (배치에는 있음) |
| `cool_overlap` | 사이클 중 cool 이 켜졌는가 | exchanger 혼자 못 잡는 횟수 | ○ |

### 1-2. 탱크 일별 (오전 6시 경계)

| 변수 | 정의 | 의미 |
|---|---|---|
| **exchanger ON 중앙값 / p90** | 그날 가동 중 사이클의 on_duration | 복귀 시간 추세. 비율·기울기 판정의 주 입력 |
| 10분 초과 건수 | 규칙 ② 에 걸린 수 | 문턱 이벤트의 빈도 추세 |
| **cool 동반 비율** | cool_overlap 사이클 / 전체 | 규칙 ③(10회 연속)보다 먼저 올라가는 성능저하 전조 |
| 사이클 수 / 시간 | 가동 시간당 사이클 수 | 부하 지표. 다른 지표를 해석할 때 보정용 |
| **min_margin** | min(PV − L_Set) | **heater 쪽.** 여유가 줄어드는 추세면 heater 가 약해진다는 신호. 이미 `TankRealtime` 이 추적한다 |
| min_pv / min_t | 그날 최저 PV 와 그 시각 | 해석용 |

heater 메시지는 `"설정 온도 도달 시간 증가 추세"` 인데, 지금 규칙 ① 은 PV 와 L_Set 만 보고 heater 신호는 안 본다.

| P4 | `워킹 Tank 2-2 HARD  Heater` |
| P5 | `워킹 Tank 3-2 CUSH  Heater` |
| I1 | `워킹 Tank 1 ISO Heater` |
| I2 | `워킹 Tank 2 MDI  Heater` (exchanger/cool 은 "2-2 MDI", heater 는 "2 MDI") |

공백 개수가 탱크마다 다르니 위 그대로 써야 한다.

## 2. 헤드 (인젝션)

### 2-1. 먼저 풀어야 할 문제 — 사이클 경계 잡기

`HDn_Pn_인젝션_ON_T / OFF_T` 는 정수(초)이고, **사이클이 끝날 때만 갱신되고 그 사이엔 이전 값을 유지**한다.
그래서 8초 다음에 또 8초가 오면 값이 안 바뀌어 사이클이 끝났는지 알 수 없다. 실측 1.5시간 동안 SOL 이 297번 켜졌는데 ON_T 값이 바뀐 건 137번뿐이었다. **추세는 사이클 단위 수열이 있어야 하므로 이 문제를 먼저 풀어야 한다.**

**해결: SOL 켜짐·꺼짐 시점을 사이클 경계로 쓴다.** 9/15 07:00~08:30, HD1 기준 실측:

| 타이머 | 갱신 시점 | HD1_P1 | HD1_P2 |
|---|---|---|---|
| ON_T | **SOL 켜짐** 0.3초 이내 | 100% | 73% |
| OFF_T | **SOL 꺼짐** 0.3초 이내 | 97% | 69% |

→ SOL 이 켜질 때 ON_T 를, 꺼질 때 OFF_T 를 읽으면 값이 같아도 사이클마다 하나씩 기록된다.

SOL 태그와 펌프 대응:

| 펌프 | SOL 태그 | 확인 |
|---|---|---|
| HD1_P1 | `Head_1 Injection SOL` | ○ |
| HD1_P2 | `Head_1-2 Injection SOL` | ○ (일치율 70% 대 — 원인 확인 필요) |
| HD2_P1, HD2_P2 | `Head_2 Injection_2 SOL` 하나뿐 (PNP 는 `후진감지1`, `후진감지2` 둘) | **미확인** |
| HD3_P1 | `Head_3 Injection SOL` | 미확인 (이름으로 추정) |
| HD3_P2 | `Head_3-2 Injection SOL` | 미확인 |
| HD4_P1 | `Head_4 Injection SOL` | 미확인 |

**확인이 필요한 점:** SOL ON 펄스는 1.1~1.6초인데 ON_T 는 8~10초다. 즉 **ON_T 는 SOL 이 켜져 있는 시간이 아니다.** ON_T·OFF_T 가 정확히 무엇을 재는지는 PLC 래더로 확인해야 한다.
같은 이유로 `후진감지 (PNP)` 는 로그상 SOL 과 같은 시각에 바뀌어서, 로드 이동 시간을 따로 뽑을 수 없었다.

### 2-2. 헤드 사이클 단위 (SOL 이벤트마다 1개)

| 변수 | 정의 | 의미 |
|---|---|---|
| **ON_T** | SOL 켜짐 시점에 갱신된 값 | 지금 문턱(≥17) 의 대상. 추세의 주 입력 |
| **OFF_T** | SOL 꺼짐 시점에 갱신된 값 | 지금 문턱(≥10) 의 대상 |
| ON_T 여유 | PLC SV(20) − ON_T | 알람까지 남은 여유. SV 가 바뀌어도 맞게 판정된다(`_FLT_SV` 태그) |
| OFF_T 여유 | PLC SV(11) − OFF_T | 위와 같음 |
| 사이클 간격 | SOL 켜짐 사이 시간 | 생산 속도. 다른 지표를 해석할 때 보정용 (HD1_P1 중앙값 13.2초) |
| SOL ON 길이 | SOL 켜짐 ~ 꺼짐 | 보조 지표 (중앙값 1.1~1.6초) |

### 2-3. 헤드 롤링 / 일별

**값이 정수 초라는 점을 고려해야 한다.** 8초에서 9초로 바뀌면 한 번에 12% 가 뛴다. 그래서 평균 한 개보다 아래 지표가 더 민감하다.

| 변수 | 정의 | 왜 |
|---|---|---|
| **ON_T 롤링 평균 (최근 50~100사이클)** | 많이 평균 내면 1초보다 작은 변화가 보인다 | 8.0 → 8.4 같은 서서히 늘어나는 변화를 잡는다 |
| **기준값 +1초 이상 비율** | 최근 N사이클 중 ON_T ≥ 기준 중앙값 + 1 의 비율 | 정수 값에 맞는 분포 이동 지표 |
| 문턱 근접 비율 | ON_T ≥ 15 (또는 SV − 5) 인 사이클 비율 | 문턱 17 에 닿기 전의 전조 |
| 일별 ON_T 중앙값 / p99 | 오전 6시 경계 | 기울기 판정 입력 |
| 일별 ≥17 건수 | 지금 규칙에 걸린 수 | 이벤트 빈도 추세 |
| OFF_T 도 같은 세트 | | |

## 3. 확인할 것 (우선순위 순)

1. **ON_T · OFF_T 의 정확한 정의** — PLC 래더 확인. SOL 펄스(약 1초)와 ON_T(8~10초)가 맞지 않는다.
2. **SOL ↔ 펌프 대응** — 특히 HD2 (SOL 1개 / PNP 2개). HD3·HD4 도 SOL 켜짐·꺼짐과 갱신 시점이 맞는지 HD1 과 같은 방식으로 확인한다. HD1_P2 일치율이 70% 대인 이유도 확인한다.
3. **heater 신호 채터링** — exchanger 의 90초 병합을 그대로 써도 되는지 OFF 길이 분포로 확인한다.
4. **기준값 기간** — 지금 데이터는 4주, 한 계절뿐이다. 계절이 바뀔 때 기준값 갱신이 따라가는지는 데이터가 쌓여야 볼 수 있다.
