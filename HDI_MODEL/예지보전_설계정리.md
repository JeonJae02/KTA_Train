## 1. 목적과 구조

한 모델로 다 하지 않고 세 층으로 나눈다. 아래층의 출력이 위층의 입력이 된다.

| 층 | 판정 시점 | 방법 | 결과 | 받는 쪽 |
|---|---|---|---|---|
| **① 실시간** | 틱마다 (~0.5초) | 틱 AE + 규칙 (타임아웃, 압력 초기 체크) | 틱별 점수 → 알림 | 라인 |
| **② 사이클** | 사이클 끝 + 3초 (~11초) | 사이클 AE | 사이클별 점수 | 기록 |
| **③ 추세** | 짧은 창(수 분) / 긴 창(일·주) | ①②의 점수 + 건강 지표의 추이 | 지속 이상, 드리프트 → 정비 시점 | 라인 / 정비팀 |

- 학습하는 모델은 **틱 AE, 사이클 AE 두 개**, 펌프마다 한 세트
- ③ 은 처음엔 통계(이동평균·EWMA·CUSUM)로 하고, 고장·정비 이력이 쌓이면 모델로 바꾼다
- ① 과 ② 가 둘 다 필요한 이유: 틱 AE 는 "지금 이 순간의 상태", 사이클 AE 는 틱 하나로는 존재하지 않는
  **모양 정보**(목표 도달 시간, 꺼진 뒤 감쇠, 안정구간 흔들림)를 본다
- **한 사이클로 판단할 수 있는 한계가 있다.** 정상 사이클끼리도 압력 상승폭이 ±5% 흔들리고, 이 흔들림은
  사이클 안의 틱을 더 모아도 줄지 않는다. 미세한 이상(10% 수준)은 **여러 사이클을 모으는 ③ 짧은 창**이 맡는다

### 데이터 흐름

   ├─ 켜진 뒤 1.6초     → 압력 초기 체크 (r_early < 0.7) ──→ ① 알림

                      사이클 기록 테이블 (점수 + 건강 지표 + 플래그)
                                   ↓

## 3. SV (레시피) 를 다루는 방법

SV 는 유량·압력을 거의 결정한다 (η² FT 0.98, PT 0.93). 클래스도 심하게 불균형하다
(상위 7개가 90.9%, 최대/최소 4,086배). 한 가지로 해결되지 않아 문제마다 따로 처리한다.

| 문제 | 처리 | 근거 |
|---|---|---|
| 레시피마다 값의 **수준**이 다름 | **SV 를 AE 입력에 연속값으로** 넣는다. 앞단 정규화 안 함 | SV 를 빼면 오차 54%↑. 앞단 정규화는 추정 오차가 섞여 오차 2.8배↑ |
| 처음 보는 SV | 연속값이라 AE 가 **내삽**. 기준표도 내삽 | 6일 안에 SV 2430 이 실제로 새로 나옴. 원-핫이었다면 z = +16.6σ |
| 표본 수 **불균형** | **클래스 균등 샘플링** — 단, 가중치 상한 필요 | 클래스별 오차 배수 0.70~2.03 → 0.76~1.29 |
| 클래스마다 **흩어짐**이 다름 | 임계값을 **SV 에 따라** 둔다 (클래스별 또는 SV 곡선) | 균등 샘플링 후에도 SV 2850 오차 1.29배. 포화 구간이라 실제로 더 흔들림 |
| 규칙의 "평소 값" | **기준표 `E(SV)`** — 클래스 중앙값, 없거나 적으면 내삽 | 압력 상승률 `r` 의 분모 |
| 추세에서 레시피 구성 변화 | **클래스 안 편차**로 모은다 | 날마다 SV 구성이 바뀌면 건강과 무관하게 평균이 움직임 |

- 불균형 자체는 오차의 주된 원인이 아니다. 편상관으로 보면 SV 값이 표본 수보다 3배 강하다
  (SV +0.622 / 표본수 −0.210). SV 2210 은 n=122 로 드문데 오차가 가장 낮다
- **균등 샘플링의 가중치는 상한을 둬야 한다.** `1/n` 그대로면 n=1 인 SV 2310 사이클 하나가 전체 배치의
  1/15 을 차지해 수천 번 반복된다. `1/max(n, 50)` 이나 `1/√n` 으로 완화하고, 모델 만들 때 비교한다

## 4. ① 틱 AE

### 상태 4개

| 상태 | 정의 | 비고 |
|---|---|---|
| idle | `BuildUp = 0` 이고 복귀 구간 아님 | **학습·판정 안 함**. 인코딩 `(0,0,0)` |
| 증압 | 켜짐 ~ **FT 곡선 꺾임** 전 | |
| 안정 | 꺾임 이후 ~ 꺼짐 | |
| 복귀 | 꺼진 뒤 3초 (다음 사이클이 먼저 시작하면 거기까지) | 밸브·씰 누설 신호 구간 |

**증압 → 안정 경계 = FT 곡선 꺾임** (5% 목표권 기준 폐기)

- 꺾임: 실제 FT 기록점 사이 기울기가, 최대 기울기가 나온 뒤 처음으로 **최대의 20% 미만**으로 떨어진 구간의 시작점.
  SV 를 쓰지 않고 자기 곡선만 본다 (10~20% 중 최종값은 틱 AE 만들 때 결정. 10↔20% 88%, 20↔30% 92% 동일)
- 목표권 기준을 경계로 쓰면 **펌프가 약해져 목표권에 못 들어갈 때 사이클 전체가 "증압" 으로 붙어**
  이상이 스스로를 숨긴다. 꺾임 기준은 안정값이 낮아져도 곡선이 눕는 순간 안정으로 넘어간다
- 곡선 모양: **압력은 첫 틱에 이미 다 오르고**(PT 1틱째 자기 안정값의 1.00), **유량은 1~2틱 늦게**
  따라온다(0.05 → 0.56 → 0.96). 경계는 FT 로 잡아야 한다
- 한계: 증압이 FT 기록점 2~3개로 끝나 정밀도는 기록점 하나(0.5~1초). 실시간에서는 다음 기록점이 와야 판정

### 입력

| 규칙 | 조건 | 잡는 것 | 근거 (가상 고장) |
|---|---|---|---|
| **FT 타임아웃** | 켜진 뒤 **3.0초** 까지 FT 가 목표권(SV ±3%) 밖 | 유량 부족 | 정상 최대 2.52초. 유량 10% 부족도 98% |

## 5. 압력 상승률 `r` 과 기준표 `E(SV)`

압력 신호의 공통 단위. 한 번 정의하고 시점만 달리해서 쓴다.

```
r = (PT − P0) / E(SV)

P0    : 켜지기 직전 PT (PreBuildUp_PT) — 그 사이클의 바닥 압력
E(SV) : 그 SV 에서 평소 오르는 양 = 학습 구간 정상 사이클의 (PT_Steady − P0) 중앙값
```

| 이름 | 계산 | 시점 | 쓰는 곳 |
|---|---|---|---|
| `r_tick` | 그 틱의 PT | 매 틱 | 틱 AE 입력 |
| `r_early` | 1~3틱 PT 최대 | 1.6초 | 실시간 규칙 (`< 0.7`) |
| `r_steady` | 안정 구간 PT 중앙값 (사출 제외) | 사이클 끝 | 사이클 AE 입력, ③ 짧은 창·긴 창 |

- **P0 를 빼는 이유**: 꺼진 상태 압력 P0 도 안정 PT 와 같은 정도로 온도를 따라간다 (−0.59 vs −0.61).
  빼면 온도 상관이 −0.61 → **−0.21** 로 준다. 온도를 따로 보정하지 않아도 바닥 압력이 기준점 역할을 한다
- `E(SV)` 는 스케일러처럼 **학습 때 만들어 모델과 함께 저장**한다. 학습 구간에서만 만든다
- 처음 보는 SV·표본 적은 SV(n < 50)는 **이웃 SV 사이 내삽**

```python
E_table = (train["PT_Steady"] - train["P0"]).groupby(train["SV_class"]).median()

def expected_rise(sv):
    return E_table[sv] if sv in E_table.index else np.interp(sv, E_table.index, E_table.values)
```

## 6. ② 사이클 AE — 피처

### 유량·증압

| 피처 | 결정 | 근거 |
|---|---|---|
| `SV` | 연속값 입력 유지 (`SV_mean` 은 쓰지 않음) | 3절 |
| `FT_mean` | 유지 | 클래스 제거 후 잔차에 정보 |
| `RampUp_Time_Sec` | **`t_cross` 로 교체** | 틱 양자화 제거 |
| `Ana_Out_mean`, `FT_max` | **제외** | SV 의 결정적 함수 / 남은 게 잡음 |
| `PreBuildUp_FT` | **제외** | 96% 가 1271~1300. 펌프가 꺼지면 유량계가 정지값으로 돌아감 |
| 꺼짐 시각 | 사이클 피처로는 **안 씀** (틱 AE 경계로만) | 아래 참고 |

### 압력

| 피처 | 정의 | 대체하는 것 |
|---|---|---|
| `r_steady` | 5절 | `PT_mean`, `PT_max` |
| **유로 저항** | `(PT_Steady − P0) / FT_Steady^2.5` | `DeltaP_over_Q`, `Current_Proxy_I` |
| `P0` | 켜지기 직전 PT | (유지) |
| `PT_Steady_Std` | 안정 구간 PT 표준편차, **사출 제외** | `Steady_Std_PT`, `PT_std` |
| `PT_Jump_From_Pre` | **제외** | 첫 기록이 상승의 몇 % 지점에서 찍혔는지를 봄 (0~1 에 고르게 분포) |

**`r_steady` 와 유로 저항은 둘 다 넣는다.** 정상에서는 같은 값(클래스 내 상관 0.994)이지만 분모가 달라 고장 때 갈라진다.

| 고장 | `r_steady` (평소 대비 압력) | 저항 (실제 유량 대비 압력) |
|---|---|---|
| 펌프 약화 | ↓ | 그대로 |
| 노즐·필터 막힘 | ↑ | ↑ |
| 바이패스·누설 | ↓ | ↓ |

- 저항의 지수: 같은 SV 안에서는 FT 변동이 0.22% 라 지수가 1 이든 2 든 결과가 같다 (클래스 내 상관 0.994).
  레시피 간 비교에서는 **2.5** 가 가장 맞다 (η² n=1 0.90 / n=2 0.47 / **n=2.5 0.04**)
- 온도 영향을 줄이는 건 지수가 아니라 **P0 를 빼는 것** (지수와 무관하게 −0.22)
- 기존 `DeltaP_over_Q` 는 `Tick ≥ 2` 부터 평균이라 증압·사출 틱이 섞였다. 3% 진입 이후·사출 제외로 다시 계산하면 η² 0.28 → 0.105
- 기존 `Steady_Std_PT` 는 사출 횟수와 +0.32 상관 (중앙 3.99 중 대부분이 사출 딥). 사출 제외 시 1.67, 상관 −0.002.
  다만 안정 틱이 중앙 6개만 남아 추정이 거칠다

### 아직 검증 안 한 것

`Decay_Slope_*` (복귀 구간), `Unexplained_*` 카운트 계열 (99.8% 가 0), `N_Ticks`

### `t_cross` — 목표 도달 시각

**정의**: 펌프가 켜진 순간(`BuildUp` 0→1 첫 틱)부터 FT 가 목표권 **SV ±3%** 에 처음 들어간 순간까지의 시간(초).
들어간 순간은 틱 사이를 보간한다.

```
p = 0.03
j = min{ i : |FT_i − SV| ≤ p·SV }                  # 목표권 첫 진입 틱
k = j−1 에서 시작, FT_k == FT_(k−1) 인 동안 k 감소   # 직전의 실제 기록점 (묵은 값 건너뜀)
L = 0.97·SV   (FT_k > 1.03·SV 이면 1.03·SV)         # 넘은 선
t_cross = t_k + (L − FT_k) / (FT_j − FT_k) × (t_j − t_k)
```

- 예외: 끝내 미진입 → `NaN` (사이클 AE 에 안 넣고 타임아웃 규칙이 처리), 첫 틱부터 목표권 → `0`, `FT_j == FT_k` → `t_j`
- 두 기록점 사이를 직선으로 보고 비례식으로 선과 만나는 시각을 찾는 것. `k` 로 거슬러 가는 건 직전 틱 FT 가
  ffill 된 묵은 값인 경우(53%) 때문
- 변환 없이 사용 (왜도 −0.11). SV 의존(1.49 → 2.00초)은 AE 가 SV 입력으로 흡수
- 직전 SV·직전 FT·공백 시간과 무관 (같은 SV 안 |r| < 0.04). 사이클 사이 약 5초 동안 펌프가 완전히 멈춰
  매번 같은 출발선(약 1285)에서 시작하기 때문

```python
def ramp_crossing_time(t, ft, sv, p=0.03):
    t, ft = np.asarray(t, float), np.asarray(ft, float)
    inside = np.abs(ft - sv) <= p * sv
    if not inside.any():
        return np.nan
    j = int(np.argmax(inside))
    if j == 0:
        return 0.0
    k = j - 1
    while k > 0 and ft[k] == ft[k - 1]:
        k -= 1
    L = (1 + p) * sv if ft[k] > (1 + p) * sv else (1 - p) * sv
    if ft[j] == ft[k]:
        return t[j]
    return t[k] + (L - ft[k]) / (ft[j] - ft[k]) * (t[j] - t[k])
```

**3% 를 고른 근거** (노트북 11장)

| 기준 | 정상 진입률 | 진입 후 다시 나감 | 토출 5% 저하 시 이동 |
|---|---|---|---|
| 1% | 97.1% | 48.2% | — (불가) |
| 2% | 100% | 0.3% | SV 2850 하위 5% 안정값(0.979)이 선 바깥 |
| **3%** | 100% | 0.1% | **2.20σ** |
| 5% | 100% | 0.1% | 0.54σ — 둔감 |

선이 안정값에 가까울수록 약해진 곡선이 막판 느린 구간에서 선을 넘어 민감해진다.
3% 여유가 가장 좁은 곳은 SV 2850 (표본 64개, 0.9%p) — 운영 중 정상 미진입이 나오면 3.5~4% 로 넓힌다.

**SV 가 높을수록 길어지는 이유**: 고SV 에서는 펌프가 도달하는 안정값이 목표선에 가까워(안정값/SV 0.996 → 0.984)
곡선이 선에 닿기 전에 눕기 시작한다 (막판 기울기 −31%). 포화의 흔적이라 지우면 안 되는 정보다.

**꺾임 시각을 사이클 피처로 안 쓰는 이유**: 레시피 무관(η² 0.010)은 장점이지만, 값이 FT 기록 시각에 묶여
틱 격자처럼 양자화된다. 가상 열화에서 토출 저하에는 원리상 0σ, 응답 둔화 10% 에도 0.55σ (`t_cross` 0.80σ).
두 경우 모두 `t_cross` 가 더 민감하다.

## 7. 알림 규칙 — 방향 확정, 숫자는 모델 완성 후 결정

### 틱 AE 점수

| 단계 | 조건 | 처리 |
|---|---|---|
| 즉시 | 한 틱이라도 극단값 | 바로 알림 (급고장은 한 틱 단차로 나타남) |
| 확인 | 구간 내 **3틱 중 2틱** 보통 임계값 초과 | 알림 |
| 기록 | 그 외 | 알림 없이 기록 → ③ |

- 3틱 **평균은 쓰지 않음** — 한 틱 튐에 넘어가고, 지속된 중간 수준은 놓침
- **히스테리시스**, **한 사이클의 한 구간당 알림 1회**
- 창은 **구간이 바뀌면 리셋**, 임계값은 **구간별·SV 별**
- 창은 틱 개수보다 **시간 또는 FT 갱신 틱 기준**
- 처음엔 **알림만**, 오경보율 확인 뒤 PLC 자동 조치 연결
- 숫자 결정 기준: 정상 구간 시간당 오경보 수 + 알람 사이클(`Dirty`)을 몇 틱 만에 잡는지

### 압력 관련 규칙 (확정값)

| 층 | 규칙 | 잡는 것 | 시점 | 정상 오경보 |
|---|---|---|---|---|
| PLC | 기존 저압 알람 | 압력 거의 없음 | 즉시 | — |
| ① | `r_early < 0.7` (1.6초까지) | ≥40% 부족 | 1.6초 | 0건 / 5.7일 |
| ① | FT 3% 목표권 3.0초 타임아웃 | 유량 부족 | 3초 | 0건 |
| ③ 짧은 창 | 최근 **10사이클** `r_steady` 평균 **< 0.93** | 미세하지만 계속되는 부족 (10%) | 약 1.5분 (7사이클) | 0건/일 |

- 기준을 0.95 로 올리면 하루 11회 오경보 — 0.93 이 적정
- 5.7일 0건은 "절대 안 뜬다" 가 아니다. 표본 크기로 보면 최대 하루 0.5회 수준까지 가능
- 짧은 창에서 5% 부족은 놓친다. 정상 상태의 상승률이 온도 등으로 몇 분 단위 ±5% 오르내리기 때문
