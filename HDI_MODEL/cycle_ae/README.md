## 구조

```
캐시 사이클 + 기준선 JSON ─→ 잔차 피처 ─→ 묶음별 표준화 ─→ 공용 조건부 AE ─→ 패턴 점수 ─┐
                                                   └──→ 피처별 |z|/한계 최댓값 ─→ 수준 점수 ─┴→ 사이클 등급
                                                                                       └→ WindowTracker (최근 10사이클) → 펌프 등급 → 알림
```

## 판정 — 두 단계 (2026-10-08 결정)

| 등급 | 임계값 (묶음별, 정상 건강일 점수 분위) | 쓰임 |
|---|---|---|
| 주의 | 0.995 (정상 상위 0.5%) | 대시보드·기록. 작은 드리프트는 ③ 추세에서 다시 본다 |
| **알림** | 0.999 (정상 상위 0.1%) | 사람에게 |

- **사람에게 가는 알림** = 펌프 창 등급(그 펌프 묶음들의 최근 10사이클 중앙값 판정 중 최고)이 **알림으로 새로 올라간 순간 한 번**
- 펌프가 30분 넘게 멈추면 창 상태를 비운다(`RESET_GAP_MIN`) — 아침 재가동 때 이상이면 새로 알림
- 알림 뒤 60분은 같은 펌프를 다시 알리지 않는다(`COOLDOWN_MIN`)
- 알림 이유 = 최근 10사이클 중 주의 이상 사이클들의 이유 최빈값
- **정상 날 알림: 펌프당 하루 0.34회, 14대 합계 약 5회.** 분위별 비교는 `cycle_ae_test.ipynb` §8

| | 내용 |
|---|---|
| 묶음 (`group`) | **펌프 × 안정 출처(clean/shot) × 단일/다단 Hz**. 표준화·임계값 단위. 출처와 다단 여부에 따라 압력 수준·곡선 모양이 달라서 |
| 복원 피처 (8) | `pump_resid`, `r_phys`, `t_self`, `decel_half_sec`, `release_half_sec`, `ft_cv`, `pt_std`, `P0` — 묶음별 학습 구간 중앙값·MAD 로 표준화 |
| 조건 (6, 복원 안 함) | 점도, Hz/묶음 대표 Hz, 직전 Hz 변화, ISO 여부, 사출 중 안정값 여부, 다단 여부 |
| 안 넣은 것 | SV 기준 피처(FT_SV, t_cross …) — Auto-Cal 마다 바뀐다 |
| 네트워크 | (8+6) → 32 → 16 → **4** → (+6) → 16 → 32 → 8, 결측은 손실에서 제외 |
| 학습 데이터 | 기준선이 고른 **평소 배관 상태** 시간대의 사이클(`role=fit`), 펌프마다 같은 비중. 약 26만 사이클 |
| 임계값 | 묶음별, 두 단계. 사이클: 학습에 안 쓴 건강일(`calib`) 점수 분위 — 패턴·수준 각각 (calib 100개 미만이면 fit+calib). 짧은 창(같은 묶음 10사이클 중앙값): fit+calib 분위 |
| 범위 밖 | 학습 사이클 300개 미만 묶음(P4·I4 의 shot 등) — 점수 NaN, `in_scope=False` |

**Hz 는 레시피 전체 범위를 다룬다.** "단일/다단" 은 사이클 **안에서** Hz 가 바뀌는지다. 기준선·모델 모두 모든 레시피의 Hz 를 쓴다.

**경보를 패턴과 수준 둘로 하는 이유.** AE 는 피처 사이의 평소 관계를 배운다 — 배관 저항이 올라 P0·`r_phys` 가 **같이** 오르는
이동은 잘 복원해 못 본다(I1 저항 증가 AE 42%). 한 피처의 수준 이탈은 수준 점수가 본다(88%). 점수를 평균 대신 최댓값으로 해도 같았다.

**수준 점수를 피처별 한계로 나누는 이유.** 그냥 최대 |z| 를 쓰면 양자화로 MAD 가 아주 작은 피처(P7 다단 레시피의 pump_resid,
척도 0.08%)가 평소에도 |z| 20 을 넘어 임계값이 포화됐다 → P7 유량계 고장의 다단 사이클을 10% 만 잡았다. 나눈 뒤 99%.

## 한계 — 다음에 할 것

1. I7·I3 압력 기준은 데이터로 판단했다(baseline/README). 현장 확인 결과가 다르면 `PT_OVERRIDE` 를 고치고 다시 학습.
2. 기준선은 펌프의 **주된** 출처로 맞춘 하나다. 다른 출처 사이클은 묶음별 중앙값을 빼서 치우침을 지우지만,
   Hz 에 따라 달라지는 치우침은 남는다. 필요하면 기준선도 출처별로.
3. 학습 데이터 4주, 묶음별 calib 날짜 1~3일 — 임계값이 거칠다. 데이터가 쌓이면 `extract_pump_cache.py` 로 이어 받고 다시 학습.
4. 짧은 창 임계값은 학습 구간 고정 기준이다. 서서히 오는 드리프트가 "새 정상" 이 되는 경우(정비 없이 오래 지속)는
   ③ 추세 층과 기준선 재학습 규칙(new_pump_preprocessor.md 5절)으로 다룬다.
5. 다단 사이클의 곡선 모양 피처(`t_self` 등)는 사이클 전체 기준이라 단계 전환이 섞여 있다. 단계별 모양이 필요하면 전처리기 수정.
